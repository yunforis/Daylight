## Cloud full-stack validation — 2026-10-17 (resolution)

All of the blockers above were resolved on the cloud verification instance and the full nine-service topology now runs. Evidence: `docs/submission/deployment/evidence/compose-*.{log,txt}` and `docs/submission/deployment/README.md`.

- **MinIO tag.** `minio/minio:RELEASE.2025-04-22T22-12-26Z` (and the other April tags) returned 502/403/denied for one layer blob on every reachable mirror — the same symptom as the earlier content-ingestion failure, still tag-independent. Moving the server tag to `RELEASE.2025-09-07T16-13-09Z` pulled normally and shares a digest with `latest`. `docker-compose.yml` now pins that tag. `minio/mc:RELEASE.2025-04-16T18-13-26Z` was never the problem and is unchanged.
- **Image build in a restricted network.** The runtime stage's `apt-get update` hung against the default Debian Fastly CDN on a dual-stack host. Added a `DEBIAN_MIRROR` build arg (default `deb.debian.org`, cloud uses `mirrors.aliyun.com`) plus `Acquire::ForceIPv4 "true"` inside the image. The build then completed and produced `daylight:local` (271 MB, Node v22.23.3, UID 1000).
- **Container runtime.** `docker.io` 29.1.3 + `docker-compose-v2` 2.40.3 installed via apt; `/etc/docker/daemon.json` sets four `registry-mirrors` and `json-file` log rotation (`max-size=10m`, `max-file=3`). `alpine:3.20` pulled in 5 s.
- **One-click bring-up.** `docker compose --env-file /opt/daylight/compose.env -p daylight up -d --wait --build` returned exit 0 in 11 s (cached layers). All nine services reached the expected terminal state: `api`/`worker`/`scheduler`/`postgres`/`redis`/`rabbitmq`/`minio` healthy, `migrate` and `minio-init` `Exited(0)`. Dependency ordering is enforced by healthchecks and `service_completed_successfully`, not by sleeps.
- **Health and shutdown checks that were previously unverified.** `/health/live` and `/health/ready` returned 200 for `api`; `worker` and `scheduler` readiness returned `ok:true` with live metrics (`dropped=0`, `sinkError=null`). Public `http://121.40.101.8:3000/` served the frontend (HTTP 200, 3240 bytes) once the security group allowed TCP 3000.
- **Loopback dependency ports.** PostgreSQL/Redis/RabbitMQ/MinIO now publish on `127.0.0.1:15432/16379/15673+15674/19000+19001`. Host-side tooling (`scripts/verify-*.mjs`, `scripts/load-test.mjs`, `scripts/probe-pg-commit.mjs`, `npm run metrics:report`) enforces loopback dependencies by design, so this is required to run them against a Compose stack; nothing is bound to a public interface.
- **Re-verification on the Compose topology.** Full suite **517/517, 0 failed, 0 skipped** (containerized PostgreSQL/Redis/RabbitMQ, `DAYLIGHT_VERIFY_PRODUCTION=1` + `DAYLIGHT_VERIFY_CONCURRENCY=1`); `verify-jobs` 8/8; `verify-production` 12/12; `verify-oss` 14/14 against MinIO; `verify-real-mail` 9/9 with real QQ IMAP and a real model call (`api.modelverse.cn`, `deepseek-v4.1-flash`, 2199 ms).
